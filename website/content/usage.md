# 第一次使用
从控制台认识流程版本和运行记录，再完成一个明确的分析场景。

## 登录与工作区 {#console}

管理员登录后进入 `/operations` 运维控制台，用于查看分析产品、Integration 任务、运行事件和已校验输出。新部署尚未导入产品或提交任务时，空列表是正常状态。

研发入口为 `/overview`，流程画布为 `/`。管理员与流程维护者使用研发功能；实际操作权限由账号角色控制。管理员账号按快速安装指南自行创建。

## 体验流程编排 {#editor}

在独立试用环境中可导入仓库的编译演示，不创建默认测试密码：

```bash
docker compose exec backend python backend/manage.py seed_demo
```

进入研发工作区，选择示例流程，检查工具、节点与参数，运行校验并预览 WDL。工具与流程发布后形成固定版本；修改草稿不会改写已发布版本。

> 编译演示用于认识画布、校验和版本机制。完整的生信执行还需要镜像、数据与参考资源；不要把编译通过当作真实流程验收。Fastp → BWA 编译示例也不作为已准备好全部依赖的运行包。

## 完成一次运行 {#run}

先完成 [快速安装的 smoke](/docs/quickstart/#verify)，确认执行环境能启动真实容器。正式业务试跑前，由流程维护者提供已发布的产品代码、契约版本、输入要求、镜像与资源清单。

1. 准备完成复制的脱敏输入，使用平台可读取的受管路径或已配置对象引用。
2. 读取固定分析产品，核对契约摘要与运行条件。
3. 预检参数与数据，通过后幂等提交任务。
4. 在运维控制台或业务后端跟踪状态与事件。
5. 执行成功后读取输出清单，验证必需文件、大小与 SHA-256。

具体 API 操作见 [接入指南](/docs/integration/)。流程选择和算法参数以该产品版本的契约为准。

## 看懂状态 {#states}

| 状态 | 含义与操作 |
| --- | --- |
| queued | 已排队，检查 Worker、资源与等待原因 |
| preparing / running | 准备或执行中，持续同步状态 |
| cancel_requested | 取消处理中，等待真实终态 |
| succeeded | 执行成功，继续核对输出完整性 |
| failed / canceled | 执行终态，保留错误或取消证据 |

执行成功、文件交付成功、业务解析成功是不同状态。列表是摘要视图，结果详情要读单次运行或输出接口。运维列表展示最近 200 条的查询范围，不等同于所有历史任务统计。

## 重试与修改流程 {#changes}

网络超时先按原外部执行 ID 找回任务，不能直接创建第二次分析。真实重跑会生成新任务并保留旧记录；由业务发起的任务应从业务系统重跑，维持样本与执行记录的对应关系。

修改流程时发布新的产品版本，明确选择后再使用。已有任务继续保留提交时的版本、输入与契约证据。

## 留下一份可复现记录 {#record}

记录底座版本、分析产品版本、资源版本、运行环境、输入规模、耗时、错误码与输出摘要。遇到问题从 [问题反馈](/docs/feedback/) 生成记录；准备扩大使用范围前完成 [测评清单](/docs/evaluation/)。
