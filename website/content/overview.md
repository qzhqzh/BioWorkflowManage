# 认识底座
BioWorkflowManage 将分析流程作为独立服务，供业务系统通过 API 调用。

## 它负责什么 {#capabilities}

- **分析产品**：固定流程、输入输出契约、镜像与参考资源版本。
- **输入预检**：校验参数和可读取的数据引用，报告未满足的运行条件。
- **执行管理**：使用 MiniWDL 或 Nextflow，记录队列、进度、事件、取消与重试。
- **结果交付**：提供语义输出、文件清单、大小与 SHA-256，支持可选回调和异步导出。
- **管理界面**：维护工具、流程与版本，查看真实运行记录。

## 怎么放进现有系统 {#architecture}

业务后端通过 `/api/v1/integration` 调用底座。业务用户、订单、样本管理、审批和报告展示继续由业务应用负责。

```text
业务应用后端
    ↓ Integration API
分析底座：产品契约 → 输入预检 → 执行管理 → 结果交付
    ↓ 已发布流程决定执行引擎
MiniWDL / Nextflow
```

底座保留自己的数据库、执行目录与 Worker。业务应用只依赖公开契约，不共用底座数据库，也不直接遍历内部结果目录。

## 三类版本分别维护 {#versions}

| 对象 | 当前约定 |
| --- | --- |
| 底座软件 | v1.1.0，固定源码与依赖锁 |
| Integration API | 路径 v1；OpenAPI 文档修订号 1.7.0 |
| 分析产品 | 固定 analysis_code、contract_version、contract_digest |

业务流程可按自己的版本迭代。新增流程需要底座尚未提供的能力时，再协调底座升级。既有产品版本不能原地改绑到新的流程。

## 当前交付范围 {#scope}

基础版提供源码、正式 Release、API 契约与部署文档。采用 Docker Compose 从源码构建；流程使用的工具镜像、私有源码和大型参考数据须按实际产品准备。

> 当前主路径是联网源码部署。完整的双引擎离线安装包尚未交付。平台可执行受信任流程，不提供任意脚本的恶意多租户隔离。

WDL 与 Nextflow 使用统一的投递和结果协议，脚本语言与运行参数各自独立。底座不负责算法结论或业务报告规则。

## 从哪里开始 {#start}

1. [快速安装](/docs/quickstart/)：独立环境中启动服务，完成首次执行验证。
2. [第一次使用](/docs/usage/)：登录控制台，认识流程与运行记录。
3. [接入指南](/docs/integration/)：固定产品契约，接入业务后端。
4. [试部署与测评](/docs/evaluation/)：记录证据，判断下一步是否进入生产评审。
