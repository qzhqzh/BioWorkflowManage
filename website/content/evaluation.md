# 试部署与测评
先固定一个环境和一个流程，验证真实链路，再决定扩大使用范围。

## 本轮怎么推进 {#cadence}

| 阶段 | 交付证据 | 下一步条件 |
| --- | --- | --- |
| 首次试部署 | 版本、环境、启动记录、smoke 结果 | 可以重复安装，执行链路可用 |
| 单流程验证 | 固定产品、输入规模、运行和输出证据 | 结果符合该流程预期 |
| 业务联调 | 幂等、超时找回、状态与结果入库记录 | 成功与失败路径都可解释、可恢复 |
| 生产评审 | 容量、隔离、备份恢复、监控与责任人 | 遗留问题有明确处理，相关负责人确认 |

先使用独立环境和脱敏小数据。每轮只改变明确的一类变量，保留上一轮版本和结果，方便定位问题。检查项只记录你的人工确认，不会自动判定生产可用。

## 首次部署 {#installation}

- [ ] 已记录操作系统、CPU/内存、Docker/Compose 版本及底座提交。
- [ ] 新环境可以按指南完成安装，管理员可登录，健康检查通过。
- [ ] MiniWDL smoke 成功，命令退出码与输出证据已保存。
- [ ] 数据目录、Worker 权限、磁盘空间与备份位置已确认。

## 流程与结果 {#workflow}

- [ ] 已固定分析产品、契约摘要、镜像和参考资源版本。
- [ ] 完整输入可正常执行，缺失或错误输入能被明确拒绝。
- [ ] 关键输出、大小与 SHA-256 通过核对，流程结果已与参考结果比较。
- [ ] 输入变动、执行失败和取消路径已验证，历史记录可追溯。

## 业务联调 {#integration}

- [ ] 相同幂等请求复用同一任务，冲突请求被拒绝。
- [ ] 投递超时可按外部执行 ID 找回，不重复创建分析。
- [ ] 服务重启与乱序响应后可恢复状态，结果不会重复入库。
- [ ] Token 权限和任务归属满足隔离要求，凭据未进入浏览器或日志。

## 生产前评审 {#production}

- [ ] 代表性数据规模与并发下的耗时、内存、CPU、磁盘峰值已测量。
- [ ] 已演练数据库和文件恢复，并记录恢复时间与可接受的数据丢失窗口。
- [ ] HTTPS、网络边界、执行隔离、监控告警和结果保留策略已确认。
- [ ] 升级与回滚方案、故障责任人及所有阻断问题已有明确结论。

版本发布和平台 CI 是起点，不代替你所在环境的容量验收、流程正确性或业务上线评审。涉及临床或其他受监管业务时，还要由相应业务负责人完成其专业验证。

## 问题如何进入迭代 {#iteration}

先用 [反馈模板](/docs/feedback/) 记录底座、流程与业务应用版本，并附复现步骤和脱敏证据。维护者判断问题属于底座、流程、业务适配还是部署配置，再确定修复归属。

| 影响 | 处理节奏 |
| --- | --- |
| 数据/结果错误、权限边界或不可恢复风险 | 阻断扩大使用，优先定位并复测 |
| 安装失败、核心链路不可用 | 修复后回到失败步骤，补一次完整链路验证 |
| 可绕过的使用问题 | 记录绕过方式与影响，安排补丁验证 |
| 文案、交互与新能力建议 | 汇总后排期；新增能力评估契约与版本影响 |

兼容修复通常进入补丁版；需要新底座能力时规划次版本。流程更新独立发布。一次迭代完成后，反馈中应补充修复版本、复测结果及遗留项。

## 保存测评结果 {#export}

勾选进度仅保存在当前浏览器。使用上方“下载测评记录”导出 Markdown，再填写环境、流程版本和证据。清除浏览器数据或换设备后需重新记录。

每轮给出明确结论：继续试用、修复后复测，或进入有条件的生产评审。勾选完成不自动产生上线批准。
