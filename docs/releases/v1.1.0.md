## 基础版职责

- 提供 Service Account 与 scope、固定分析产品目录、输入预检、幂等投递和超时找回。
- 通过 MiniWDL / Nextflow 执行适配器运行受信任流程，维护队列、租约、事件、取消和重试。
- 固定输入、流程与契约快照，区分执行状态与输出完整性，提供校验下载、可选异步导出和签名 Webhook。
- 提供流程维护与管理员运维控制台；运维列表明确显示最近 200 条的查询范围。
- 保留内嵌数据索引；独立数据服务和跨引擎并发上限按部署配置显式启用。
- 支持显式声明的固定 Panel 与有界、不可变 BED 输入，已有分析产品继续使用其原始契约。

业务应用负责用户业务、样本、订单、审批、报告规则和展示。分析流程包负责算法、输入输出、
工具镜像和参考资源绑定。业务功能或流程内容变化不自动要求升级底座；需要新增执行能力时，
发布新的底座版本，并由流程发布记录明确最低底座版本。

## 兼容与升级

本次发布整理相对于已交付功能基线为 **internal**：版本与文档变更不改变运行行为。
相对于上述主线契约基线，Panel 与服务拆分为 **additive**；数据所有权切换属于显式 **migration**。
详细约束见[平台契约与兼容开发约定](../22-integration-contract-governance.md)。

- 保留既有 Integration API 历史基线，不修改已发布分析产品或历史任务快照。
- `DATA_SERVICE_URL` 未配置时继续使用内嵌索引；迁移到独立数据服务必须遵循
  [切换与回滚说明](../24-data-service-extraction.md)，不能只修改 URL 后忽略旧状态。
- `ANALYSIS_MAX_ACTIVE_RUNS=0` 保留旧行为；启用大于零的跨引擎并发上限要求 PostgreSQL，
  所有执行 Worker 使用一致配置。
- 旧 LC103 / Panel 产品保持原契约。使用上传 BED 能力时显式发布并选择新产品，见
  [Panel 接入说明](../24-panel-selection.md)。
- 从历史 `v1.0.0` 升级时先备份并核对迁移、输入与输出清单、列表摘要及详情读取方式，
  参照[历史升级说明](../18-stable-release.md)和当前接口定义；不能把从已交付功能基线发版
  等同于从任何历史部署无条件直接替换镜像。

发布标签不执行客户数据库迁移、切换数据服务、替换流程或更改凭据。实际升级由部署方在维护窗口
验证旧请求、固定产品、状态查询与结果交付；回滚保留数据库、原始数据、运行记录与流程版本。

后续维护以兼容为前提：修复使用补丁版本，可选新增能力使用次版本；涉及公共行为迁移时先给出
并行契约、接入顺序和回滚方案，不因升级软件版本覆盖已有流程产品。
