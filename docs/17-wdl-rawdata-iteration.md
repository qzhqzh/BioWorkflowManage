# WDL 协作与原始数据体验迭代

## 目标

产品重心继续放在多人维护 WDL：让维护者能快速判断哪个资产需要处理、最近是谁做了什么，并从完整审计记录进入源码工作台。原始数据管理作为运行前准备环节，负责只读检查 `rawdata` 目录，让操作人员在提交任务前发现配对、空文件和命名问题。

## 本轮落地

### WDL 维护视图

- 历史 WDL 列表增加“全部 / 待处理 / 已通过”维护状态筛选。
- 维护状态来自当前不可变 revision 的解析诊断，不新增人工维护的重复状态。
- 列表展示最近协作人、动作、备注、版本和时间；详情页仍是完整 diff 与审计事实源。
- 不改变现有并发协议：元数据写入继续要求 `base_metadata_version`，源码写入继续要求 `base_version` 与 `base_digest`。

### 原始数据中心

- 扫描受管 `workspace/rawdata`，识别 `.fastq.gz` 和 `.fq.gz` 的 R1/R2 配对。
- 分开呈现可运行、缺配对、空文件、重复 mate、无法识别命名和扫描受限状态。
- 支持按目录、状态和关键词筛选，并展示文件大小、修改时间和相对路径。
- 只有完整且非空的数据集进入运行分析；从详情可直接带入并自动选中。
- 页面和 API 均只读，不提供上传、改名、移动或删除。

## 验收标准

1. 一组完整、非空的 R1/R2 能在原始数据页显示“可运行”，也能出现在运行分析下拉框。
2. 缺 R2 或包含空文件的数据集显示具体问题，且不能进入运行分析。
3. 以 FASTQ 结尾但不符合 R1/R2 命名的文件单独列出，不被静默忽略。
4. 普通运行用户只能访问原始数据与运行分析；WDL 维护者和管理员保持完整权限。
5. 从原始数据详情进入运行分析后，目标数据集自动选中。
6. WDL 列表能筛出当前有错误或提醒的资产，并显示最近协作人的操作与备注。
7. 桌面与窄屏页面均可完整滚动，无横向页面溢出；状态不只依赖颜色表达。

## 后续路线

### P1：评审与交接

- 在 immutable revision 之上增加评审请求、评审结论和指派人，不把评审状态混入源码内容。
- 增加“等待我处理”视图，聚合冲突、解析错误、待评审和被指派资产。
- 支持在 revision 上做行级评论；评论解决和重新打开都进入审计事件。

### P1：原始数据清单持久化

- 为超大目录增加后台增量索引和上次成功扫描快照，避免每次页面请求遍历 NAS。
- 记录数据集首次发现、最近变化和运行引用关系，文件身份变化时阻止复用旧投递。
- 扫描阈值和目录深度改为部署配置，并在页面展示管理员可执行的修复建议。

### P2：WDL 发布治理

- 为资产增加可配置的发布检查模板，例如“语法通过、imports 完整、工具包版本固定、至少一条小数据验证”。
- 将评审、发布和运行验证串成可查询的版本证据链，但不允许页面状态覆盖不可变 revision。
- 提供跨资产协作动态与维护 SLA，用于团队周检而不是装饰性统计。

## 非目标

- 本轮不移动、重命名、上传或删除用户的原始数据。
- 本轮不读取 FASTQ 内容，不做 reads 质量分析。
- 本轮不运行生产大数据流程，只用小型目录样本验证扫描和选择链路。
- 本轮不重构 WDL 编辑器或改变已经上线的写入 API。
